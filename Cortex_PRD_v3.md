# PRD - Product Requirements Documens
## Cortex — Predictive Brain-Engagement Video Optimizer

**Version:** 3.0 (Engineering Spec — Cursor-Ready)
**Event:** HackRice 16
**Track:** Finance & Entrepreneurship
**Sponsor stack (locked):** Gemini API, ElevenLabs (video + audio), TigerData (exploratory), Vultr (exploratory)
**Core inspiration:** Percept (formerly Cerebra) — UC Berkeley AI Hackathon 2026 Finalist — used Meta TRIBE v2 as a predicted brain-engagement reward model to score short-form video ads. Cortex adapts that same TRIBE v2 scoring approach into a **human-in-the-loop analyze → select → redo → choose → replace** workflow.
**Personas:** Intentionally scrapped for this version — to be added in a later revision.
**Status:** Ready for implementation

---

## 1. Product Summary

Cortex lets a user upload a short video ad, see a real predicted brain-engagement signal (via Meta TRIBE v2) rendered as a glowing, synced timeline, manually pick the weak moment(s) they want to fix, and get 2-3 AI-regenerated versions of just that segment — generated by ElevenLabs' video platform based on a do/avoid instruction pair written by Gemini after watching the clip. The user picks their favorite, it's spliced back into the full video, and they export the final result.

**One-line pitch:** "See where your ad loses attention, then let AI redo just that moment — pick the version you like, ship the rest as-is."

## 2. Locked Tech Stack & Sponsor Roles

| Component | Tool | Role | Requirement tier |
|---|---|---|---|
| Brain-engagement prediction | **Meta TRIBE v2** | Predicts time-windowed cortical activation from video/audio/text | Core |
| Compute host for TRIBE v2 | **Vultr** (A40/L40S GPU instance) | Hosts the one-time-per-video inference pass | Exploratory (core can run on any available GPU/Colab if Vultr setup stalls) |
| Marketing interpretation | **Gemini API** (multimodal) | Watches the user-selected weak segment, writes a positive + negative prompt pair | Core |
| Video/audio regeneration | **ElevenLabs** (video generation platform: access to Veo, Sora, Kling, Seedance, Wan, etc. + native voice/music/SFX) | Generates 2-3 candidate redone versions of the selected segment from Gemini's prompt pair | Core |
| Storage / system of record + creative memory | **TigerData** | Stores activation vectors, edit-attempt history, and per-segment content embeddings (pgvector); powers similarity lookups so the redo loop knows what's already been tried | Exploratory |

**Explicitly not used:** Redis, Pika (Percept's own stack for these roles is replaced by TigerData and ElevenLabs' native video generation respectively).

## 3. Core vs. Exploratory — Feature List

### CORE (must ship — this is the demo)
- C1: Video upload
- C2: TRIBE v2 inference → time-windowed activation series (precomputed once per video)
- C3: Glowing engagement timeline synced to video playback (the "brain lighting up" visual)
- C4: Manual segment selection by the user (drag-select a range on the timeline)
- C5: Gemini watches the selected segment → generates a positive prompt + negative prompt
- C6: ElevenLabs generates 2-3 candidate redone versions of that segment from the prompt pair
- C7: User previews and selects their favorite candidate
- C8: Selected candidate is spliced back into the full video (ffmpeg)
- C9: User exports/downloads the final video

### EXPLORATORY (attempt only after Core is fully working and demo-safe)
- E1: **TigerData Creative Memory** — every generated candidate segment is stored with an embedding of its content/direction alongside its (derived) engagement data. Before/after a redo request, Cortex queries TigerData for past segments similar to the current one and surfaces their outcomes — so repeated regenerations aren't blind. Replaces flat JSON storage as the system of record for segment history.
- E2: Vultr-hosted TRIBE v2 backend (replacing any interim Colab/rented-GPU setup)
- E3: Consent Gateway — biometric face/voice matching against a consent DB before analysis runs on any video with a recognizable person (explicitly framed as a responsible-AI pattern demo, not certified compliance)
- E4: Demographic-aware critique (Gemini re-interpreting the same TRIBE v2 data per age bracket) — deferred from earlier design discussion, revisit only if Core + E1-E3 are done early

## 4. End-to-End User Flow (Core)

```
1. User uploads a short video ad.
2. [Backend] Video sent to TRIBE v2 (precomputed pass, not live-per-frame).
3. [Backend] TRIBE v2 returns time-windowed cortical activation data
   across 6 macro-regions: visual, language, reward/novelty,
   memory/familiarity, emotional/arousal, attention/salience.
4. [Backend] Cortex derives a composite engagement curve per time window
   (response strength, peak response, temporal drop-off — same
   construction Percept used, since TRIBE v2 has no built-in single score).
5. [Frontend] Video plays with a synced glow/graph beneath it — user
   WATCHES exactly where engagement is predicted to rise or fall.
6. [User action] User drag-selects a time range on the timeline they
   want redone (human judgment call, not auto-flagged).
7. [Backend] The selected segment (video+audio) is extracted via ffmpeg
   and sent to Gemini (multimodal) along with the surrounding context
   and its engagement data.
8. [Backend] Gemini returns a structured pair:
      { positive_prompt: "what the new version should do",
        negative_prompt: "what to explicitly avoid" }
9. [Backend] Both prompts sent to ElevenLabs' video generation API,
   seeded from a frame of the original segment (image-to-video mode)
   to preserve visual continuity where possible.
10. [Backend] ElevenLabs returns 2-3 candidate regenerated segments.
11. [Frontend] User previews each candidate in context (auto-spliced
    preview against the surrounding original footage).
12. [User action] User picks a favorite candidate (or discards all and
    keeps the original segment).
13. [Backend] Chosen candidate is spliced into the full video (ffmpeg),
    replacing the original selected range.
14. [Frontend] User exports/downloads the final edited video.
```

**Note on "real-time" visuals (Step 5):** the glow/graph is a **replay of precomputed data synced to playback timestamps**, not live inference happening during playback. This is both cheaper and more demo-reliable, and matches how Percept itself presented frame-by-frame attention (computed once, then shown).

## 6. Service Contracts (for Cursor to scaffold against)

### 6.1 `POST /api/videos/upload`
**Request:** multipart video file
**Response:**
```json
{ "video_id": "vid_123", "status": "processing" }
```

### 6.2 `GET /api/videos/{video_id}/activation`
Triggers or retrieves the (precomputed/cached) TRIBE v2 result.
**Response:**
```json
{
  "video_id": "vid_123",
  "duration_sec": 15.0,
  "windows": [
    {
      "t_start": 0.0, "t_end": 1.5,
      "regions": {
        "visual": 0.62, "language": 0.31, "reward_novelty": 0.44,
        "memory_familiarity": 0.20, "emotional_arousal": 0.55,
        "attention_salience": 0.58
      },
      "engagement_score": 0.51
    }
  ]
}
```

### 6.3 `POST /api/videos/{video_id}/segments/redo`
**Request:**
```json
{ "t_start": 4.0, "t_end": 7.0 }
```
**Backend behavior:** extracts segment → sends to Gemini → sends result to ElevenLabs → returns candidates. In parallel [EXPLORATORY], embeds the segment and queries TigerData for similar past segments; `similar_segments` is attached if the lookup resolves, and omitted if it doesn't (it must never block the candidates).
**Response:**
```json
{
  "segment_id": "seg_45",
  "positive_prompt": "Show the product within the first second, upbeat energetic pacing, warm lighting matching the original shot.",
  "negative_prompt": "No dead air, no static wide shot, no generic stock-ad phrasing.",
  "candidates": [
    { "candidate_id": "cand_1", "preview_url": "..." },
    { "candidate_id": "cand_2", "preview_url": "..." },
    { "candidate_id": "cand_3", "preview_url": "..." }
  ],
  "similar_segments": [
    {
      "segment_id": "seg_12",
      "similarity": 0.87,
      "positive_prompt": "Show the product within the first second, upbeat pacing.",
      "selected_candidate_id": "cand_2",
      "engagement_score": 0.74
    }
  ]
}
```
*`similar_segments` is [EXPLORATORY] — Core ships this response without that key.*

### 6.4 `POST /api/videos/{video_id}/segments/{segment_id}/select`
**Request:**
```json
{ "candidate_id": "cand_2" }
```
**Backend behavior:** splices chosen candidate into the full video.
**Response:**
```json
{ "video_id": "vid_123", "status": "spliced", "preview_url": "..." }
```

### 6.5 `GET /api/videos/{video_id}/export`
**Response:** final video file / signed download URL.

### 6.6 [EXPLORATORY] `POST /api/consent/check`
**Request:** video_id
**Response:**
```json
{ "status": "approved" }
```
or
```json
{ "status": "pending_verification", "unmatched_identity_id": "id_9", "verification_method": "sms" }
```

## 7. Data Model

```
Video {
  id, source_url, uploaded_at, duration_sec,
  consent_status  // "approved" | "not_required" | "pending"  [EXPLORATORY]
}

ActivationWindow {
  video_id, t_start, t_end,
  regions: { visual, language, reward_novelty,
             memory_familiarity, emotional_arousal, attention_salience },
  engagement_score
}

Segment {
  id, video_id, t_start, t_end,
  positive_prompt, negative_prompt,
  candidates: [ { candidate_id, preview_url, model_used } ],
  selected_candidate_id
}

CreativeMemory {   // [EXPLORATORY]
  id, video_id, segment_id,
  embedding,              // vector, pgvector column
  positive_prompt, negative_prompt,
  selected_candidate_id,  // null if none chosen yet / discarded
  engagement_score,       // from the composite curve, if available
  created_at
}


ConsentRecord {   // [EXPLORATORY]
  id, video_id, identity_id, match_status, verification_method, resolved_at
}
```
*Core build: this can live as flat JSON per video_id on disk/local DB. Exploratory build: migrate to TigerData.*

## 11. Non-Functional Requirements & Honesty Contract

- TRIBE v2's public inference is a **population-average** prediction — no per-individual or literal demographic-specific brain measurement is being claimed (demographic interpretation is deferred to E4 anyway in this version).
- The composite engagement curve (response strength/peak/drop-off) is Cortex's own scoring construction on top of TRIBE v2's raw output, following Percept's precedent — TRIBE v2 itself does not output a single "good/bad" score.
- The glowing timeline during normal playback is a **replay of precomputed data**, not live per-frame inference — state this plainly if asked.
- ElevenLabs-generated segment replacements are AI-generated video, not the original footage — any real deployment beyond a hackathon prototype would need clear on-video disclosure of AI-altered content.
- TRIBE v2 weights are CC BY-NC-4.0 — non-commercial, prototype only.
- [EXPLORATORY] If built, the Consent Gateway must be explicitly described as a responsible-AI pattern demonstration, not a certified biometric-compliance system.
- Performance targets: segment redo request (Gemini + ElevenLabs round trip) — acceptable to take 10-30s given real video generation latency; communicate this with a clear loading state, don't pretend it's instant.
- Reliability: full offline fallback using precomputed/cached results and pre-generated candidate segments for all locked demo videos.

## 13. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| ElevenLabs video generation doesn't preserve continuity with original footage | Use image-to-video mode seeded from the original segment's first frame; test early Saturday, not late |
| ElevenLabs video credit budget runs out mid-hackathon | Check plan tier's seconds-per-month allowance before repeated testing; reserve real credits for final demo assets, use cheaper/faster models for early iteration |
| TRIBE v2 / Vultr GPU setup delays | Get inference working on any GPU Friday night; Vultr migration is Phase 2, not a blocker |
| Gemini/ElevenLabs live latency during demo | Pre-generate and cache full walkthroughs (including all candidate segments) for locked demo videos as a guaranteed fallback |
| Scope creep into demographic critique (E4) or Consent Gateway (E3) before Core is solid | Hard cut line at end of Section 10 — Core ships first, always |
| Creative memory adds latency to the redo loop (embed + query on every request) | Run the similarity lookup async/in parallel with the ElevenLabs generation call, not serially before it — attach results when both resolve |
| Not enough segments generated during the hackathon for similarity search to feel meaningful in the demo | Pre-seed TigerData with a handful of synthetic/precomputed segment embeddings for the locked demo video(s) before presenting, so the first live query already has real matches to return |
